# OCR 방식 검토 보고서 v0.2 — OCR 솔루션 vs 비전 LLM(VLM)

작성: 엄규현 / v0.1 2026.07.30 → v0.2 2026.07.31(gemma3 실측 기입·판정) / 검증용 모델: gemma3(12B, 비전 — 운용 대상 Gemma 4 31B의 축소 검증판)

## 1. 배경
- 당초 사이냅 OCR 도입 전제 → Gemma의 이미지 입력(비전) 지원으로 VLM 문자인식 대안 대두
- 정량 실측으로 결정하기 위한 검증 체계(골드셋·지표·도구) 구축 및 베이스라인 측정

## 2. 구조적 차이
| 구분 | OCR 솔루션 | 비전 LLM |
|---|---|---|
| 원리 | 글자 모양(글리프) 분류 — 인쇄체 전제 | 시각 패턴+문맥 결합 해석 |
| 강점 | 결정적 동작·글자별 신뢰도·CPU 고속 | 표 붕괴·저품질·필기에 강함, 인식+구조화 통합 |
| 약점 | 필기 인식 불가, 라이선스 반입 | GPU 필요, 신뢰도 없음, 환각 |
| 실패 양상 | 깨진 글자(가시적) | 그럴듯한 생성(비가시적 — 더 위험, 방어 필수) |

## 3. 비정형(필기) 문서
- OCR: 흘림체 한글 구조적 인식 불가(자모 붕괴), ICR도 자유 서술 필기엔 취약
- VLM: 문맥 기반 부분 판독 가능한 유일한 수단 — 단 환각(특히 필기 숫자) 최고 위험
- **중간 결론: 필기 문서는 VLM 외 대안 없음 → VLM 경로는 어느 결정에서도 필요. 쟁점은 인쇄체 통일 여부**

## 4. 검증 체계
- 골드셋: 04 영상판독지 5쪽 수기 전사(`data/eval/ocr_gold/`) — 유형×품질×필기로 15~20쪽 확장 예정
- 지표(`scripts/eval_ocr_accuracy.py`): CER / **숫자CER(환각 치명도, 우선)** / 필드 정밀도·재현율 / 판독불가율(정직성)
- 판정: VLM이 숫자CER ≤ OCR && 필드재현율 ≥ OCR 이면 대체 가능 신호

## 5. 실측 결과 (골드셋 5쪽 — gemma3는 260dpi·3타일, 개선판 vlm_ocr)
| 엔진 | CER | 숫자CER | 필드 P/R | 판독불가율 | 비고 |
|---|---|---|---|---|---|
| tesseract(kor+eng) | 19.7% | 21.0% | 0.96/0.95 | — | 베이스라인 |
| **gemma3 12B (VLM)** | 20.5% | **6.9%** | **1.00/1.00** | 22.8% | 260731 실측 — 31B의 하한 성능 |
| 사이냅 OCR | (실측 기입) | (실측 기입) | (실측 기입) | — | 동일 골드셋 산출물 확보 시 |

- 페이지별 gemma3: p1 CER 15.1%/숫자 0.7% · p2 19.4%/0% · **p3 33.8%/32.1%(이상치)** · p4 11.0%/0.7% · p5 23.4%/1.1%
- **판정: 대체 가능 신호 충족** — 숫자CER 6.9%≤21.0%, 필드재현율 1.00≥0.95 (4장 판정식 성립)
- 해석 3가지:
  ① 업무 치명 지표(숫자·필드)에서 압승 — p3 제외 시 숫자CER 0~1%로 등록번호·검사시각·의사번호 무오류
  ② CER 20.5%는 tesseract와 유사해 보이나 성격이 다름 — tesseract는 오독(비가시적 위험), VLM은
    ⟦판독불가⟧ 정직 신고(판독불가율 22.8%)가 오류로 집계된 몫이 큼. 신고 페이지는 검수 큐로 회수됨
  ③ p3(수치 밀집 표 추정)만 숫자CER 32.1% 이상치 — 해당 유형은 검수 필수 유지, 원문 재확인 필요
- 12B(맥북 축소판) 결과이므로 31B에서 판독불가율·CER 개선 여지 큼 — 숫자·필드는 이미 기준 통과

### 5.1 실제 산출물 대조 (스크린샷은 docx판 수록)
- ①스캔 원본(04 판독지) ②tesseract vs 골드 대조 ③실제 운용 OCR 산출 txt 발췌(개인정보 마스킹) 3종 수록
- 관찰: 오픈소스 OCR 오독은 서식 헤더에 집중("등록번호"→"SS HS"), 본문 인쇄체는 정확
- 관찰: 실제 운용 OCR은 글자 정확도가 높으나 표 서식이 줄 단위로 흩어져 "라벨 따로 값 따로" 산출 — LLM 후처리(필드 재조립)가 필수인 실증 근거이며, VLM 전환 시 이 재조립 품질이 비교 대상

## 6. 운영 구성 대안
① VLM 단독(인식+정제 통합, 라이선스 불요 — 환각 방어·GPU 설계 필수) / ② 병행 라우팅(인쇄=솔루션, 필기·저품질=VLM) / ③ 솔루션 유지(현행 설계 — 필기는 사각지대)
- 잠정 권고: 필기용 VLM 경로 선행 구축(완료 — vlm_ocr.py), 인쇄체는 실측 수치로 결정

## 7. 리스크·안전장치
- 환각 방어: 전사 전용 프롬프트(창작·요약·번역 금지, ⟦판독불가⟧), temperature 0, 기계검사(반복·과소·숫자 생성), 검수 필수 큐
- GPU: 페이지당 수 초~수십 초 → OCR 야간 배치 분리, 별도 인스턴스(Q4 18GB) 권장
- 전제: FabriX 이미지 입력 지원 확인(미지원 시 vLLM 등 비전 서빙 반입 추가)
- VLM은 신뢰도 점수 없음 → DB 신뢰도 컬럼은 기계검사 기반 파생값으로 성격 변경
