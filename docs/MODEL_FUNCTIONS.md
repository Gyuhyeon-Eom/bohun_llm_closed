# 보훈심사 AI 지원 시스템 — 모델별 기능사항

작성일: 2026. 7. 27. / 근거: 코드베이스 전수 조사(생성 LLM 호출 12지점, 임베딩 검색·색인 15지점, OCR 파이프라인 16지점)

## 1. 개요

- 본 시스템은 AI 모델을 **4계층**으로 사용한다: ① 생성형 LLM(문서 초안·질의응답·OCR 정제), ② 임베딩 모델(의미 검색·RAG), ③ 문자인식 OCR, ④ 규칙·그래프(모델 미사용 결정 로직).
- 생성형 LLM은 내부망 **API 서빙(OpenAI 호환 규격)** 으로 호출하며, 애플리케이션은 모델명 설정(`FABRIX_MODEL` 등)만으로 모델을 교체할 수 있다(코드 수정 불필요).
- 운용 모델은 **GPT-OSS-120B, Gemma 4 31B** 1~2종을 상정하고, 기능 성격에 따라 배정한다(4장). 두 모델 모두 Apache 2.0 라이선스로 폐쇄망 반입·업무 사용에 제약이 없다.
- 공통 원칙: **초안·추천은 AI, 확정은 담당자(HITL)**. 원문에 없는 사실 생성 금지. 최종 산출물(심의의결서 조립·XLSX·PDF)은 LLM을 사용하지 않는 결정적 조립.

## 3. 기능별 모델 사용 현황

### 3.1 문서접수(OCR) 단계

| 기능 | 사용 시점 | 입력 → 출력 | 호출 빈도 | 모델 |
|---|---|---|---|---|
| 스캔 문자인식 | 텍스트층 없는 PDF 인제스트 | 페이지 이미지(200dpi) → 텍스트 | 페이지당 1회 | tesseract(kor+eng) |
| OCR 전문 교정 | 정제 도구(ocrrefine `--correct`) | 블록 원문(2,400자 조각) → 교정 전문 + 수정내역(fixes) diff | 블록·조각당 1회 | **Gemma 4 31B** |
| OCR 필드 정제 | 정제 도구(ocrrefine `--llm`) | 하위문서 원문(3,600자) → JSON(문서종류·날짜·병원·상이처·등급·소견·근거문장) | 하위문서당 1회 | **Gemma 4 31B** |
| OCR LLM 정규화 | 문서접수 화면 [LLM 정규화] | 블록 원문 + 담당자 교정쌍 few-shot(최근 5건) → 정형 JSON(norm) | 블록당 1회, 실패 시 규칙 폴백 | **Gemma 4 31B** |
| 저신뢰 블록 교정 | 업로드 접수(/ingest) | 저신뢰 OCR 블록 → 교정 텍스트 | 블록당 1회 | (현재 규칙 대역 — LLM 전환 지점, **Gemma 4 31B**) |

- 안전장치: 교정 프롬프트는 **내용 창작·요약·번역 금지**를 명시하고, 산출물에 대해 안전검사(길이 급변·숫자 소실/생성·성명 바꿔치기 감지)를 통과하지 못하면 **원문을 유지**한다. 인적사항(성명·주민번호)은 LLM 투입 **전에** 규칙으로 마스킹한다.

### 3.2 요건심사

| 기능 | 사용 시점 | 입력 → 출력 | 호출 빈도 | 모델 |
|---|---|---|---|---|
| AI 심의의결서 초안(1~3장) | [AI 심의의결서 생성]·란별 재생성·우선순위 확정 재생성 | 란별 작성지침(실물 의결서 문체) + 분과 정형화틀 v2 + 사건자료(우선순위 상위 12건, 3장은 법령 RAG 발췌 추가) → 란 텍스트 | 란당 1회(일괄 시 3회 연속) | **GPT-OSS-120B** |
| 종합판단 판단내용(4장) | 종합판단 팝업 [판단내용 생성]·[종합판단 업데이트] | 담당자 선택 이원판단 + 사건 기록 일체(경위·병적·유사사례·판례·의무기록) + 분과 모듈·매뉴얼 발췌 → 판단내용 본문(결론 문안은 결정적 조립) | 상이처당 1회 | **GPT-OSS-120B** |
| 자체검증(리플렉시온) | 판단내용·검토서 생성 시 자동 | 초안 + 근거자료 → 지적사항(critique) → 수정본(revise) | 생성 1건당 검증 1~N회 | **GPT-OSS-120B** |
| 유사사례 사유 요약 | 유사사례 [AI 왜 유사한지]·상세 팝업 | 본 건 상이처 요약 + 과거사례 판정·요약 → 65자 내외 한 문장(캐시) | 사례당 1회(멱등) | **Gemma 4 31B** |
| 자료 한 줄 요약 | 관련 자료 팝업 [AI 요약] | 사건 요약 + 미요약 자료 목록 → 자료별 45자 요약 JSON 일괄 | 안건당 1회 | **Gemma 4 31B** |
| AI 사전 판단(추천값) | 종합판단 팝업 자동 표시 | 유사사례 판정 분포·의무기록·복무상태 → 추천값+신뢰도+근거 | — | 룰 기반(**LLM 미사용**) |

### 3.3 AI 챗봇 (RAG 질의응답)

| 기능 | 사용 시점 | 입력 → 출력 | 호출 빈도 | 모델 |
|---|---|---|---|---|
| 챗봇 답변 생성 | 워크스페이스 챗봇·안건별 질의 패널 | 하이브리드 검색 상위 근거(문서명·페이지) + 판단기준 룰그래프·지식그래프 사실 + 대화 6턴 → 답변+출처 | 질의당 1회(+재검색 시 재생성) | **Gemma 4 31B** |
| 질의 재작성 | 근거 미확인 시 자동 | 원질문 + 1차 검색 컨텍스트 → 재작성 검색어 1줄 | 질의당 0~N회 | **Gemma 4 31B** |

- 검색 자체(하이브리드: 벡터+키워드 RRF)는 bge-m3 임베딩과 PostgreSQL이 수행하며 LLM은 **답변 문장화만** 담당. 근거 없는 내용은 "확인되지 않습니다"로 답하도록 프롬프트 고정.

| 기능 | 입력 → 출력 | 모델 |

### 3.6 개발·평가 도구 (배치, 화면 없음)

- 정규화 모델 비교 평가(`scripts/eval_normalize_models.py`): 동일 프롬프트를 후보 모델들에 투입해 JSON 안정성·필드 정답률·속도 실측 → **모델 선정·교체 시 근거 산출 도구**.
- RAG 평가 심판(`scripts/eval_rag.py --judge`): 질문·근거·답변을 LLM이 1~5점 채점.

## 4. 모델별 기능사항 요약

### 4.1 GPT-OSS-120B — 심층 추론·장문 생성 담당

- 배정 기능: 심의의결서 초안(1~3장), 종합판단 판단내용(4장), 자체검증(critique/revise), 검토서 자동생성, 대화형 통계(Text-to-SQL).
- 배정 사유:
  - 법령 요건 적용·판단 서술 등 **다단계 추론이 필요한 장문 생성**에서 오픈웨이트 최상급 추론 성능(OpenAI 공개, 추론 특화 MoE).
  - 총 117B 규모이나 토큰당 활성 5.1B라 **대형 모델 품질을 상대적으로 낮은 추론 비용**으로 제공, 80GB GPU 1장에 탑재 가능.
  - 판단내용은 안건당 호출 수가 적어(상이처당 1회 + 검증 1~2회) 대형 모델 지연을 수용 가능.

### 4.2 Gemma 4 31B — 고빈도·정형 추출 담당

- 배정 기능: 챗봇 답변·질의 재작성, OCR 전문 교정·필드 정제·정규화, 유사사례 사유 요약, 자료 한 줄 요약.
- 배정 사유:
  - 질의당·블록당 반복 호출되는 **고빈도 기능은 경량 dense 모델의 낮은 지연**이 체감 품질을 좌우.
  - 한국어 포함 140+ 언어 지원, **256K 컨텍스트**로 장문 스캔 전문 교정에 여유.
  - Q4 양자화 시 18GB로 **소형 GPU에도 배치 가능** — 120B와 별도 자원으로 병행 서빙 용이.
  - JSON 고정 출력·창작 금지형 **정형 추출 과업**은 31B급으로 충분함을 개발 단계 실측(로컬 대체 모델 비교 평가)으로 확인.

### 4.3 (참고) 생성 LLM이 아닌 모델·로직

- **bge-m3 임베딩(1024차원)**: 챗봇 하이브리드 검색, 신청 경위 기반 유사사례, 법령·판례·분과 매뉴얼 발췌(의결서 3장 자료), 별표3 기준 대조(등급예측), 코퍼스 색인(법령·판례·매뉴얼·실무지침·스캔 정리본). 개발 환경은 hash 대체, 운영 전환 시 모델 디렉토리 반입 후 설정 변경.
- **tesseract 5(+kor)**: 텍스트층 없는 스캔 PDF 문자인식(200dpi 실측 최적).
- **규칙·그래프(모델 미사용)**: AI 사전 판단(룰 점수화), AI 등급예측 사유문(별표3 원문 결정적 인용), 지식그래프 다중홉 사실, 누락서류 판단, 최종 산출물 조립(의결서·XLSX·PDF), 개인정보 마스킹.

## 5. 운용 구성(1모델/2모델)과 전환 방법

- **권고: 2모델 병행** — 생성 품질(120B)과 응답 속도·자원 효율(31B)을 기능별로 최적화.
- **1모델 운용 시**: GPT-OSS-120B 단독을 권고(전 기능 커버, 활성 5.1B라 챗봇 지연도 수용 범위). Gemma 4 31B 단독도 동작하나 종합판단·초안 품질은 내부망 실측 비교(3.6 평가 도구) 후 판단.
- 전환 방법: 모델명은 환경설정으로 교체(`FABRIX_MODEL`). 현재 코드는 전역 단일 모델 구조이며(OCR 정제 도구만 정제/교정 모델 분리 지원), **기능별 2모델 분리 운용 시 설정 항목 추가(경량 작업용 모델명) 소규모 수정 필요**.
- 모델 확정·교체 시 절차: 평가 도구(3.6)로 후보 모델 실측 → 결과 JSON 비교 → 설정 변경 → 프롬프트 미세조정.

## 6. 공통 안전장치

- 전 프롬프트에 **원문에 없는 사실 생성 금지** 명시, OCR 계열은 temperature 0 고정.
- 생성물 자체검증(리플렉시온 critique→revise, 검증 실패 시 초안 그대로 통과 — 차단 관문 아님) + OCR 교정 안전검사(숫자 소실·생성, 성명 바꿔치기 감지 시 원문 유지).
- **HITL**: AI 산출물은 전부 초안·추천 상태로 저장되고 확정·수정 권한은 담당자에게 있음. 담당자 교정 이력(field_edit)은 이후 정규화 프롬프트에 few-shot으로 재주입 — 폐쇄망에서 재학습 없이 품질 누적.
- LLM 장애 대응: 연결 불가/일시 오류를 구분해 화면 안내, OCR 정규화는 규칙 폴백으로 업무 중단 방지. 토큰 사용량 호출별 로깅.
