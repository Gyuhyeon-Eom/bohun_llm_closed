# 프론트 연계 API 명세 — 개발 계약 (260803 확정)

**`보훈심사_AI_API_명세_v0.1.xlsx` 가 프론트-백엔드 개발 계약임.** 프론트 측 양식(아산시
변화탐지 API_250729 템플릿)을 그대로 따름 — API 목록 시트 + API별 명세 시트,
자녀 필드는 4칸 들여쓰기·회색(808080).

## 원칙 (이대로 개발한다)

1. **명세의 원본은 코드** — 이 명세는 `api/main.py` 실구현을 전수 조사해 작성한 것.
   구현과 문서가 어긋나면 버그로 취급한다.
2. **API 변경 절차**: 코드 수정 → 이 명세 갱신(버전 up) → 프론트 공유. 응답 필드
   제거·타입 변경은 breaking — 프론트 합의 전 금지. 필드 추가는 non-breaking으로 허용.
3. **오류 규약**: 실패 시에도 HTTP 200 + `{"error": "<사유>"}`. 프론트는 상태코드가
   아니라 `error` 키 존재로 분기한다.
4. **봉투 없음**: code/message/result 래핑 없이 데이터를 바로 반환한다.
   (프론트가 봉투 형식을 요구하면 미들웨어 래퍼로 일괄 적용 — 개별 핸들러 수정 금지)
5. **개인정보**: 평문 주민번호가 내려가는 API는 없다(rrn_masked만). 신규 API도 동일.
6. **파일 응답** (export·download·file 계열)은 JSON이 아닌 파일 스트림 — `dl=1`로
   다운로드 강제. 원본 열람은 `/scan-docs/{sd_id}/url`로 URL 발급(만료형 presigned).
