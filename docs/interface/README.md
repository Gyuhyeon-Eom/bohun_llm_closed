# 프론트 연계 API 명세 — 개발 계약 (260803 확정)

**`보훈심사_AI_API_명세_v0.9.xlsx` 가 프론트-백엔드 개발 계약임.** 프론트 측 양식(아산시
변화탐지 API_250729 템플릿)을 그대로 따름 — API 목록 시트 + API별 명세 시트,
자녀 필드는 4칸 들여쓰기·회색(808080).

## v0.2 (260803) — ID 규약
- **ID 속성명은 DB테이블정의서 v0.6 영문명**: aply_log_sn(안건)·wnd_sn(상이처)·grd_srng_sn(등급안건)·
  orgtxt_dcmnt_sn(원문서류/자료)·chbt_sshn_sn(챗봇세션)·case_sn(사례) 등 — 전체 대응은 명세 '이름매핑' 시트.
- **ID 타입은 string 계약** (연산 금지 값 — 형식이 바뀌어도 명세 불변). 프로토타입은 number로
  반환 중이며, 운용 API 구현 시 string으로 고정한다.
- 목록 API(안건·등급안건)에 search_text/필터/order/page/per_page 파라미터 — 전체 건수는
  X-Total-Count 응답 헤더 (프로토타입 구현 완료).

## v0.3 (260803) — 화면설계 기반 재구성
- **API 목록을 화면설계(피그마 BNM-U00-0100 = 화면설계서 v0.6) 기준으로 재편**: ①화면설계 반영
  ②화면설계 확인 대기 ③데모·검증용(실서버 제외) 3그룹 + 화면 요소 매핑 열.
- **신설 3종**: 안건 상세 `GET /cases/{aply_log_sn}`(구현 완료 — 안건 파라미터 직접 진입),
  의결서 전체 저장 `POST /case-draft/{aply_log_sn}/save-all`(S4-③, 구현 완료),
  e통합보훈 동기화 `POST /decision-doc/{aply_log_sn}/sync-ebohun`(S5-②, 연계 규격 TBD — 명세만).
- 확인 대기 그룹은 피그마 export/토큰 확보 시 화면ID 기입 후 v0.4로 확정.

## v0.4 (260803) — 실개발 계약판 (프론트 전달본)
- **전달본에는 개발 내부 사정 표현 없음**: 신설/TBD/프로토타입/데모/이름매핑 시트 전부 제거 —
  프론트는 "무엇을 보내고 무엇을 받는다"만 읽는다. (프로토타입 키 대응은 이 README와 코드 별칭 계층이 담당)
- 그룹: 요건심사 / 상이등급심사 / 문서접수(OCR) / AI 챗봇(우측 영역) / 자료함 / 산출물·파일.
  내부 도구(게시판·통계·검증용)는 전달본에서 제외.
- 피그마 보드 기준 화면 매핑: 요건심사·상이등급심사·우측 영역 섹션 = 최종수정본.

## v0.6 (260803) — 스코프 확정: AI(LLM) 처리 API만
- **화면 CRUD·조회는 웹 백엔드(Java) 담당** — 안건 목록/상세/자료함/작성이력/세션 조회 등은 명세에서 제외
  (자바가 DB 직접 조회). 명세는 LLM 서버가 요청받아 처리하는 것만: 자료 적재(OCR→DB)·정규화·RAG 적재·
  안건 변환 / 의결서 초안·종합판단·기준 대조 / 판정예측 / 챗봇·유사사례·AI 요약 / AI 산출물 2종.
- **최소 요청 원칙**: DB에 있는 값은 요청에 안 담음 — ID + 지시값만. 종합판단은 yeu/bosang **Y|N**,
  판정예측은 grd_srng_sn만(상이명은 서버가 DB 조회). 서버 구현 완료(Y/N 정규화·ID-only 예측).

## v0.7 (260803) — 응답 봉투·화면 액션 단위 재정의
- **응답 봉투**: 계약 API는 `{success, message, data}` — payload는 data 하위(명세에서 들여쓰기·회색).
  실패 시 success=false + message 사유(HTTP 200). 서버 미들웨어가 계약 경로에만 적용, 구화면 호환용
  최상위 병행 키 유지.
- **화면 액션 단위 API**: '의결서 자료 패키지' 등 사이트 내부 개념 제거 —
  `POST /decision-doc/{aply_log_sn}/draft`(S3-① AI 심의의결서 초안: 란 3종 일괄 생성·저장, 구현 완료)로 대체.
  판단기준 대조·근거 원문·사례 검색 등 조회성은 명세에서 제외(자바 또는 챗봇 내부 기능).
- 최종 구성: 12 API + 산출물 2 (자료 적재 5 / 요건심사 2 / 상이등급 1 / 챗봇·유사사례 4).

## 원칙 (이대로 개발한다)

1. **명세의 원본은 코드** — 이 명세는 `api/main.py` 실구현을 전수 조사해 작성한 것.
   구현과 문서가 어긋나면 버그로 취급한다.
2. **API 변경 절차**: 코드 수정 → 이 명세 갱신(버전 up) → 프론트 공유. 응답 필드
   제거·타입 변경은 breaking — 프론트 합의 전 금지. 필드 추가는 non-breaking으로 허용.
3. **오류 규약**: 실패 시에도 HTTP 200 + `{"error": "<사유>"}`. 프론트는 상태코드가
   아니라 `error` 키 존재로 분기한다.
4. **봉투 없음**: code/message/result 래핑 없이 데이터를 바로 반환한다.
   (프론트가 봉투 형식을 요구하면 미들웨어 래퍼로 일괄 적용 — 개별 핸들러 수정 금지)
5. **개인정보**: 평문 주민번호가 내려가는 API는 없다(rrn_masked만). 신규 API도 동일.
6. **파일 응답** (export·download·file 계열)은 JSON이 아닌 파일 스트림 — `dl=1`로
   다운로드 강제. 원본 열람은 `/scan-docs/{sd_id}/url`로 URL 발급(만료형 presigned).
